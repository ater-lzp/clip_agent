# 前端技术规范

## 1. 职责与目标

前端负责把长耗时、可中断、可恢复的短视频生成流程呈现为清晰可信的用户体验。实现前必须阅读根目录 `AGENTS.md`；涉及任何接口时同时阅读并维护 `agents/api.md`。

前端不得实现后端业务规则，也不得推测未定义的接口字段。发现契约缺失或不一致时，先明确契约，再修改调用代码。

## 2. 技术约束

- 使用 Vue 3、TypeScript 和 Composition API，单文件组件优先采用 `<script setup lang="ts">`。
- TypeScript 保持严格类型检查。禁止用 `any`、非空断言或类型强转掩盖接口问题；确需使用时必须缩小范围并说明原因。
- 依赖和脚本以 `frontend/package.json` 及锁文件为准。未经任务需要不得引入新的 UI 框架、状态库或请求库。
- 组件只负责展示与交互；API 调用、流程状态、领域类型和格式化逻辑分别放入明确的模块。
- 环境变量只允许包含可公开的构建时配置，例如 API 基础地址。任何供应商密钥都不得进入 `VITE_*`、前端代码或构建产物。

推荐按实际规模采用以下职责划分，已有项目结构优先：

```text
frontend/src/
├── api/          # 请求客户端、端点封装、传输 DTO
├── components/   # 可复用展示与交互组件
├── composables/  # 可复用组合逻辑
├── router/       # 路由与访问控制
├── stores/       # 跨页面状态；仅在确有需要时使用
├── types/        # 领域类型与状态枚举
├── utils/        # 无副作用工具函数
└── views/        # 页面级组件
```

## 3. 核心页面与用户流程

前端至少应能承载以下产品流程；具体范围以当前任务为准：

- 注册与登录：邮箱注册、账号密码登录、会话恢复和退出登录。
- 新建视频：输入主题描述、目标时长、横竖屏比例以及服务端允许的生成选项。
- 生成详情：展示当前阶段、已完成阶段、耗时、可恢复状态和安全的错误信息。
- 剧本审核：展示剧本版本；支持批准或填写反馈后退回，防止重复提交。
- 分镜审核：清晰呈现镜头顺序、口播、画面描述、预计时长和素材关键词；支持批准或退回。
- 预览与 BGM 决策：播放无 BGM 预览，允许选择不添加 BGM，或添加 BGM 并设置音量。
- 历史记录：按当前用户列出任务状态和最终产物，支持预览、导出和删除，并对危险操作二次确认。
- 设置：保存非敏感用户偏好和服务端允许的模型选项；不得展示、缓存或修改服务器 `.env`。

## 4. 长任务与人工审核交互

工作流是服务端事实来源。前端可缓存界面状态，但不得仅凭本地状态认定任务已批准、失败或完成。

- 使用后端定义的任务 ID 和状态枚举，不自行创建同义状态。
- 页面刷新或重新登录后，应通过任务 ID 恢复服务端状态和待审核内容。
- 轮询、SSE 或 WebSocket 方案必须以 `agents/api.md` 为准，并在组件卸载、路由切换或任务终止时释放连接和定时器。
- 只在服务端状态允许时展示操作；提交审核或 BGM 决策期间禁用按钮，成功前不得乐观地推进阶段。
- `reject` 必须提供非空反馈；`approve`、`reject`、`no_add` 和 `add` 使用契约中的明确值，不用布尔值承载多种语义。
- 处理重复点击、过期版本和已被其他会话处理的审核。遇到冲突时刷新服务端状态并给出可理解提示。
- 失败界面区分“可重试”“需要修改输入”“需要重新审核”和“不可恢复”；不得向用户显示堆栈、内部路径或供应商密钥。

## 5. API 与状态管理

- 在 `api/` 中集中配置基础地址、超时、认证、序列化和通用错误映射；页面组件不得散落裸请求。
- 请求与响应使用显式 DTO。对不可信响应在边界做必要校验，日期、可空字段和联合状态必须被准确建模。
- 401 统一清理会话并跳转登录；403 显示无权访问；409 用于版本或状态冲突；422 显示字段级校验信息；5xx 提供安全的重试入口。
- 不把服务器错误文本直接插入 DOM。用户生成的剧本、字幕和分镜默认按纯文本渲染；确需富文本时必须使用可靠的白名单清洗。
- 认证优先采用后端提供的安全 HttpOnly Cookie。若既有契约使用令牌，遵循其存储策略且不得把长期敏感令牌持久化到不安全位置。
- 任务列表和详情数据应明确加载、空数据、成功、部分成功和失败状态，避免单个 `loading` 布尔值覆盖所有并发请求。

## 6. 视频与时间轴体验

- 视频比例至少正确支持 16:9 与 9:16；播放器和审核卡片应在桌面与移动端保持可用，不拉伸画面。
- 时长统一使用秒作为传输单位，展示时通过同一个格式化函数生成 `mm:ss` 或 `hh:mm:ss`。
- 音量的单位和范围必须与 API 契约一致，并在界面标明；不自行混用 0–1、百分比和分贝。
- 字幕、镜头和音频片段按稳定 ID 关联，不依赖数组下标作为业务标识。
- 媒体加载失败时提供重试或下载入口；资源尚未就绪时不得渲染无效播放器。
- 下载文件名仅使用服务端建议的安全文件名或前端清洗后的名称。

## 7. UI、可访问性与响应式

- 优先呈现当前阶段、下一步操作和阻塞原因；生成进度不得伪造精确百分比，后端只提供阶段时使用阶段进度。
- 所有表单元素有可见标签和明确错误信息；键盘可完成核心操作，焦点状态清晰。
- 状态不能只用颜色表达；审核、失败、处理中和完成同时使用文本或图标。
- 弹窗需要焦点管理和 Escape 行为；异步结果使用适当的可访问提示，但避免频繁播报进度噪声。
- 移动端优先保障审核、预览和主要操作，不让关键按钮被播放器或底部栏遮挡。
- 保持视觉语言一致，复用设计令牌和基础组件，不在页面内复制大段样式。

## 8. 安全与隐私

- 禁止在日志、通知、URL 查询参数、localStorage、错误追踪上下文中保存密码、密钥、完整令牌或敏感生成内容。
- 外部链接使用安全属性；预览 URL、下载 URL 和重定向目标必须来自受信契约，不执行用户提供的 `javascript:` 或任意协议。
- 退出登录后清除内存中的用户数据和任务缓存，并让受保护路由立即失效。
- 删除历史记录、覆盖审核结果等高影响操作必须明确对象并二次确认；前端确认不能替代服务端鉴权。

## 9. 测试与完成标准

根据改动风险覆盖以下内容：

- 工具函数和状态转换的单元测试。
- 表单校验、按钮禁用、防重复提交和错误分支的组件测试。
- 剧本批准/退回、分镜批准/退回、刷新恢复、BGM 两条分支的关键流程测试。
- API 使用 mock，测试不得依赖真实 LLM、TTS、Pexels 或渲染服务。

提交前至少确认：类型检查通过；相关测试和构建通过；无控制台错误；页面刷新可恢复任务；空态、错误态和窄屏可用；接口变更已同步 `agents/api.md`；如用户流程、安装或配置改变，已检查并按需更新 `README.md`。
